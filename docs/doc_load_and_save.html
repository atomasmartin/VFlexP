A case in VFlexP consists of an Excel workbook (<case>.xlsx) for the network and steady-state data, optionally accompanied in the same folder by a PSS/E-style dynamic data file (<case>.dyr) and a JSON case settings file (<case>.json). This three-file format is directly compatible with VFlexPy.

Cases can be opened and saved interactively from the top toolbar of the VFlexP App (launched via vflexp or vflexp('bus_systems/4buses_hybrid.xlsx')) or programmatically via vflexp_load_case and vflexp_save_case on a VFlexPSession object.

1. Loading Grid Data from an Excel Workbook (.xlsx) or MATPOWER File (.m)

The network workbook format is based on MATPOWER-FUBM and includes sheets for Bus data, Line data, Gen data, IntConv data, System parameters, and optional sheets for Gen cost data, Parameter variation, Secondary control, Tertiary control, and Voltage sag. Standard MATPOWER .m case files can also be loaded directly or converted to Excel with fun_MATPOWER_to_Excel.

Cells in Bus data (Vm, Va) and Gen data (Pg, Qg) may contain numeric values or symbolic variable references such as $Pf_set, which are managed centrally in the Variables dialog (VariablesDialog) or in session.variables.

2. Companion Dynamic Data File (.dyr)

When <case>.xlsx is loaded, vflexp_load_case automatically checks for <case>.dyr beside it (via fun_read_dyr). The .dyr file supports:

  • Named variable declarations: $name = value / (or standalone $name = value lines), registered in session.variables and populated into the parameter sweep table.
  • Synchronous machine and control records: GENROU, GENSAL (mapped to MGES, supporting CONVERSION=CLASSICAL or CONVERSION=EXACT and COMPLEXITY="MODEL=EMT8" or "MODEL=RMS4"), ST4B (AVR), IEEEG1 (turbine governor), and PSS2B (dual-input stabiliser).
  • Converter and DC source records: GFL, VSM, GFM, DC_PES, and interface-converter records INTCONV_GFL, INTCONV_VSM, and INTCONV_GFM keyed by fbus-tbus.
  • DC grid element overrides: DCBUS (bus capacitance C) and DCLINE (line inductance L).

3. Companion Case Settings File (.json)

If <case>.json exists beside the workbook, fun_read_case_json reads the simulation horizon (t_end), Simulink solver method and tolerances (method, rtol, atol, max_step), MATPOWER power-flow solver options (tolerance, max_iterations, enforce_q_limits), and optional variables into session.config.

4. Saving Grid Data and Modular Simulink Traceability

Clicking Save in the App toolbar (or calling vflexp_save_case(session, path)) writes all current session tables—preserving symbolic $name formulas—back to an Excel workbook (.xlsx) and synchronises solver settings to <case>.json when present. Because all dynamic parameters and operating points are passed through ModelWorkspace structures (prm_*, op_*) to modular libraries in Simulink/lib/, loading or saving cases never modifies .slx files.
